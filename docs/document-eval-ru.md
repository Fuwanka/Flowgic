# Проверочный набор документов Flowgic для российского рынка

Обновление: по поручению пользователя собрана отдельная открытая подборка —
16 случаев на 24 страницах. См. [результаты и ограничения](document-eval-public.md).
На ней выполнен [локальный прогон двух конфигураций PaddleOCR](paddleocr-evaluation.md).
Ниже описан первоначальный снимок FlowVision; его показатели не включают открытые источники.

Дата подготовки: 29.10.2026. Версия протокола: 1.0.

## Что подготовлено

Инструмент `tools/document_eval/prepare.py` собирает отдельный локальный снимок
исходных изображений и постраничной разметки FlowVision. Команда не обучает модели,
не меняет FlowVision и не обращается в рабочую БД Flowgic.

Результаты находятся в `.local/document-eval-ru/v1/`: `manifest.jsonl`,
`images/`, `inventory.json`, `review.html`. Оригиналы и реквизиты остаются локальными:
`.local/` уже исключена из Git и индексации ИИ. Просмотр содержит исходные персональные
и коммерческие данные; его не следует публиковать или раздавать веб-сервером.

Это **карантин кандидатов**, а не готовый независимый benchmark. Исходную разметку
нельзя считать проверенным ответом. Отсутствующее в разметке поле получает
`unreviewed`, а не `absent`. Неизвестное происхождение и права на документ сохраняются
как неизвестные. Ранее использованные в обучении страницы не входят в holdout.

## Российские формы и каналы

Транспортная накладная (ТН), товарно-транспортная накладная 1-Т, ТОРГ-12 и УПД —
разные классы. Имя файла `ТТН` не подтверждает форму 1-Т: просмотренные файлы
FlowVision с таким именем содержат транспортные накладные.

Минтранс сообщает о переходе с 01.09.2026 на электронные перевозочные документы
и наличии исключений. Поэтому старые бумажные формы нужны для архивов и сканов,
а актуальный контур должен учитывать визуализации ЭТрН и структурированные оригиналы.
OCR печатной визуализации не подтверждает подпись и не заменяет обмен через оператора.
Точную редакцию/формат каждого нового примера фиксируем отдельно, по его источнику.

| Класс | Цель, документов | Какие варианты нужны |
|---|---:|---|
| ТН, бумажные и архивные | 40 | Разделы старых и новых редакций, экспедитор, заказчик отдельно от отправителя, несколько страниц |
| Визуализация ЭТрН | 32 | Разные операторы и макеты, QR, несколько титулов, пустые или изменённые сведения |
| Договор-заявка / заказ на перевозку | 24 | Таблица, свободная форма, перевозчик и экспедитор, плановые даты, тариф и НДС |
| ТТН 1-Т | 16 | Товарный и транспортный разделы; итоги товара отдельно от перевозки |
| ТОРГ-12 | 16 | Много позиций, перенос итогов, единицы, брутто/нетто; стоимость товара |
| УПД | 16 | Разные печатные представления, функции документа, реквизиты отгрузки и НДС |
| Отрицательные примеры | 16 | Чистый бланк, счёт, акт, путевой лист, нечитаемый снимок, неполный комплект |
| **Всего** | **160** | Целевая квота; это не число уже собранных документов |

CMR/eCMR — отдельное расширение для международных перевозок, не подмена российского
ядра. При подтверждении этого сегмента добавить не менее 16 документов сверх квоты.
XML ЭТрН/УПД — отдельная проверка парсера; не смешивать её точность и скорость с OCR.
Бланки из интернета пригодны для классификации/проверки отсутствующих значений,
но сами по себе не заменяют заполненные реальные документы.

Для каждого основного класса нужны цифровые PDF, сканы и телефонные фото. Внутри
набора отмечаем перекос, поворот, тень, сгиб, печать поверх текста, рукописные вставки,
мелкий шрифт, обрезанные края, смешение кириллицы/латиницы, пустые поля. Деградации
одного оригинала не считаются независимыми документами и не попадают в разные split.
Целевые отраслевые срезы: сборные/паллетные грузы, стройматериалы/навал, продукты/рефрижераторы.
С учётом подтверждённого пользователем профиля клиентов из 144 положительных
примеров 96 отводятся стройматериалам, по 16 — общим, пищевым/рефрижераторным
и промышленным грузам. Ещё 16 — отрицательные примеры. Это продуктовые приоритеты,
не заявление о рыночных долях. Покомплектная очередь — `acquisition.csv`.

Строительный срез: песок/щебень, бетон/раствор, цемент, арматура/металлопрокат,
кирпич/блоки, пиломатериалы, утеплитель/сухие смеси, смешанные паллеты.
Проверять т/кг, м³, м², штуки/пачки/мешки, десятичную запятую, брутто/тару/нетто,
несколько ходок по одной заявке, разные точки одного объекта, пересортицу и возвраты.
Кубометры нельзя превращать в килограммы без отдельно подтверждённых оснований.
Весовой талон и паспорт качества — смежные документы: они не должны автоматически
классифицироваться как накладная. Для товарного объёма/количества сохранять сырой
регион и единицу; не записывать объём в утверждённое поле массы.

## Реквизиты и правила разметки

Полный машинный перечень — `FIELDS` в `tools/document_eval/prepare.py` (37 полей).
Он включает номер/дату документа, роли сторон, их ИНН/КПП и адреса, маршрут,
плановое и фактическое время отдельно, описание/массу/единицу груза, места,
водителя, автомобиль/прицеп, стоимость перевозки/груза, НДС, валюту, номера
заявки и сопроводительного документа. Тип/редакция документа — метаданные записи.

Для каждого поля: `present`, `absent`, `unreadable`, `not_applicable` либо пока
`unreviewed`. Для `present` обязательны значение и evidence: номер страницы,
координаты в процентах `[x,y,width,height]`, дословный текст. Регионы одного поля
сохраняются списком, не перетираются последней страницей. Конфликтующие значения
разбираются вручную, с записью решения.

Не исправлять видимое значение ради валидного ИНН/даты. Контрольная сумма ИНН —
флаг проверки, не основание выдумывать цифры. Не восстанавливать скрытые печатью
символы по справочнику. Не считать номер заявки номером ТН, стоимость товара платой
за перевозку, грузоподъёмность массой груза, ФИО подписанта ФИО водителя.
Масса нетто/брутто указывается в evidence с квалификатором; неоднозначные варианты
требуют решения, а не молчаливого выбора. Для нескольких товаров нужны регионы/строки,
не сумма случайно найденных чисел. Время без зоны не превращать автоматически в UTC.

Сохраняем исходные пробелы/знаки в `raw_text`; нормализованные деньги — десятичные
строки, не float; номера с ведущими нулями остаются строками. Не приписываем рубли,
дату или единицу измерения, если источник не даёт такого основания.

## Независимость и допуск к оценке

1. Зафиксировать источник, разрешённое использование, форму, канал и происхождение.
2. Собрать все страницы перевозки под одним `document_id`; макеты/дубликаты и
   производные фотографии связать общей группой. SHA-256 выявляет только точные
   дубликаты; визуальные/перекодированные копии дополнительно проверяются вручную.
3. Разделять по документам, компаниям и семействам макетов. Отложить отдельные
   ранее не встречавшиеся бланки. Файлы holdout не использовать для обучения,
   подбора промпта, демонстрационных примеров и выбора порогов.
4. Два разных проверяющих подтверждают все поля и каждую страницу, включая
   отсутствующие значения. Нужны reviewer, second_reviewer и журнал разногласий.
5. Для реального holdout требуются подтверждённые права, реальное происхождение,
   отсутствие установленной экспозиции в нашем обучении и полная разметка.
   Экспозицию в предобучении публичной модели гарантировать нельзя; публичные
   учебные примеры не выдаём за заведомо неизвестные модели реальные документы.

`score_eligible` отказывает кандидатам, синтетике, неизвестным источникам,
непроверенным полям и известным обучающим примерам. Это предварительный шлюз,
не полноценный оценщик/проверка корректности всех evidence.

Текущий материал FlowVision пригоден для разработки и анализа ошибок, но новый
независимый holdout должен поступить из других, разрешённых источников. Публичная
доступность картинки сама по себе не подтверждает права на её распространение.

Метрики: точное совпадение критичных полей после согласованной нормализации,
полнота, ложные заполнения отсутствующих полей, доля документов без исправлений,
ошибки классификации, время проверки. Отдельные отчёты по форме, качеству и роли.
Итоговый балл не публиковать до заполнения квот и независимой проверки.

## Воспроизводимый запуск

```powershell
venv\Scripts\python.exe tools/document_eval/prepare.py --source C:/repository/FlowVision --output .local/document-eval-ru/v1
venv\Scripts\python.exe -m unittest discover -s tools/document_eval -v
venv\Scripts\python.exe tools/document_eval/verify.py .local/document-eval-ru/v1
```

Существующий каталог не перезаписывается. Для повторного снимка выбрать `v2`.
Инструмент использует стандартную библиотеку Python 3.11; файлы моделей не загружает.

## Фактический результат первого снимка

Собрано 28 комплектов, 52 страницы, 503 исходных региона. У 11 комплектов найдена
известная экспозиция в прежнем обучающем материале; у 17 она пока неизвестна.
Обнаружено 12 конфликтов кодов Fxxx и семантических названий областей.
Допущенных независимых эталонных документов: **0**. Все 160 слотов нового
репрезентативного набора пока требуют приобретения примеров и подтверждения.
Существующие кандидаты нельзя механически засчитать в эти слоты.

Визуально просмотрены пять разных исходных страниц: современный архивный макет
ТН, старый макет с печатью, учебный скриншот, длинный бланк с брутто/нетто и
обрезанный старый бланк. Это частичная проверка, не двойная разметка всего корпуса.
Новые подтверждённые примеры ТТН 1-Т, ТОРГ-12, УПД, ЭТрН и заявок ещё не получены.
Изображения с чужими реквизитами из поиска автоматически в корпус не включались.
