# Проверка PaddleOCR для Flowgic, 29.10.2026

Практический вывод: готовые веса PP-OCRv5 пригодны как OCR-основа MVP с проверкой
диспетчером. Для CPU предпочтителен компактный детектор; полный автоматический
импорт 37 реквизитов и промышленная готовность этим экспериментом не подтверждены.

## Фактические результаты

Основной прогон обработал все 24 страницы 16 случаев без ошибок исполнения.
Сравнение детекторов выполнялось последовательно, на одинаковых 7 страницах,
с одинаковым распознавателем и параметрами CPU:

| Показатель | Server detector | Mobile detector |
|---|---:|---:|
| Страниц в прогоне | 24 | 7 |
| Медиана на одинаковых 7 страницах | 40.676 с | 15.589 с |
| Совпавших контрольных фрагментов | 21 / 22 | 21 / 22 |
| Ошибок выполнения | 0 | 0 |
| Пиковый RSS процесса | 2071.3 MiB | 1035.7 MiB |
| Загрузка runtime и моделей, отдельно | 16.724 с | 10.522 с |

Медиана полного серверного прогона — 40.311 с, диапазон 26.004–50.826 с.
Для компактного варианта диапазон — 7.817–25.000 с. На сравниваемых страницах
компактный вариант быстрее примерно в 2.61 раза. Пики памяти относятся к разным
объёмам прогонов, это не точный прогноз памяти при любой нагрузке.

Оба варианта заменили десятичную запятую суммы встроенного УПД ВШЭ на точку:
ожидалось `19200,00`, прочитано `19200.00`. Числовая величина сохранилась,
посимвольное совпадение контрольного фрагмента отсутствует. Нормализацию денег
следует выполнять отдельно, через Decimal и явные правила, сохраняя исходный текст.

В этих выбранных фрагментах читаются русские заголовки/наименования, ИНН, дата,
ведущие нули номера, десятичная цена, нетто/брутто и суммы. Значение `21/22` нельзя
представлять как общую точность 95.45% на российских накладных.

Это одиночные локальные прогоны на рабочем компьютере с 15.7 GiB RAM; загрузочный
тест сервера и повторные статистические замеры не проводились. Результаты и входные
контрольные суммы: `tools/document_eval/paddle_smoke_results.json`.

Просмотр оригиналов рядом с OCR:

- `.local/paddle-eval/run-v2/review.html` — все 24 страницы, server detector;
- `.local/paddle-eval/run-mobile-v1/review.html` — 7 контрольных страниц, mobile detector.

Скрипты подготовки/проверки: 16 pytest-тестов прошли. Общий Django pytest
остановился до сбора тестов из-за отсутствующего SECRET_KEY; это не успешный
полный регрессионный прогон Flowgic. Бэкенд API и доменные модели не менялись.

Рекомендуемый следующий шаг — фоновый OCR worker с постоянно загруженными
компактным детектором и eslav-распознавателем, хранение текста/координат/оригинала,
слой классификации и извлечения реквизитов, проверка значений и подтверждение
диспетчером. Обучение начинать после накопления размеченных ошибок готовой системы.

## Область проверки

Проверяются локальный запуск, чтение русского текста и частичные контрольные
фрагменты на собранных открытых документах. Это не проверка всей цепочки
«накладная → 37 реквизитов → заказ», не оценка полноты таблиц и не независимый
рыночный benchmark. Полная эталонная разметка корпуса по-прежнему не утверждена.

PaddleOCR-VL-1.6 в данном прогоне не запускался. Результаты относятся к обычному
PP-OCRv5, и переносить их на VL/PP-Structure автоматически нельзя.

## Конфигурации

- Python 3.11.9, Windows x64, CPU, 4 вычислительных потока, oneDNN включён.
- PaddlePaddle 3.2.1, PaddleOCR 3.7.0, PaddleX 3.7.2.
- Основная пара: `PP-OCRv5_server_det` + `eslav_PP-OCRv5_mobile_rec`.
- Компактная пара для сравнения: `PP-OCRv5_mobile_det` + тот же распознаватель.
- Детекция ограничена длинной стороной 1600 px; входные PNG до 1800 px,
  полученные рендером оригинальных PDF. Batch распознавания — 8 строк.
- Ориентация документа, исправление геометрии и классификатор ориентации строк
  отключены. Устойчивость к перевёрнутым телефонным фото этим прогоном не доказана.
- В ML-окружение установлены отдельные зависимости; Django requirements не менялись.
- Полный снимок пакетов: `tools/document_eval/paddle_environment.lock.txt`.
- Ревизии моделей и SHA-256 файлов: `paddle_models.lock.json` и
  `paddle_mobile_models.lock.json` рядом со скриптами.

Первоначальный CPU-запуск без oneDNN прерван: он не дал завершённых страниц за
несколько минут. Это не ошибка распознавания. Рабочие замеры выполняются с oneDNN.
Диагностические сообщения `Timeout` от faulthandler в первом рабочем процессе —
дампы длительного вычисления, не завершение страницы с ошибкой; статус берётся
из `results.jsonl`.

## Проверка без внешнего API

Пакеты и официальные веса скачаны заранее. При распознавании указаны локальные
пути к обоим checkpoint, отключена проверка источников моделей, включён offline-режим
HF. Python audit hook запрещает `socket.connect` и `socket.getaddrinfo`, а процесс
запускается с ограниченной сетью. Накладные не отправляются в сервис распознавания.
Такой эксперимент подтверждает локальный путь исполнения выбранной конфигурации;
это не общий аудит сетевой активности всех возможных backend/расширений библиотеки.

Первичная загрузка весов с Hugging Face прошла с этой машины. Этот факт не
гарантирует доступность загрузок у каждого российского провайдера. Для эксплуатации
стоит хранить проверенные веса и зависимости в собственном хранилище/образе.

## Русский язык и лицензия

Официальная документация указывает русский, белорусский, украинский и английский
для `eslav_PP-OCRv5_mobile_rec`. Русский не входит в опубликованный список языков
универсальной PP-OCRv6; выбирать модель только по новизне версии нельзя.

Код PaddleOCR и выбранные официальные checkpoint опубликованы под Apache-2.0.
Лицензия допускает коммерческое использование; отдельного географического
ограничения для РФ в её тексте нет. При распространении учитывать LICENSE,
уведомления об изменениях, сохранение attribution/NOTICE, если он предусмотрен.
Это не требует раскрывать собственный код Flowgic только из-за использования OCR.
Лицензия на движок не предоставляет права на сторонние документы датасета.

Локальный запуск не требует иностранного платного API или регистрации документов
в облачном сервисе. Размещение вычислений и хранилища на собственной инфраструктуре
в РФ технически возможно; конкретное промышленное размещение здесь не выполнялось.

## Контрольные фрагменты

`tools/document_eval/paddle_checks.json` содержит 22 фрагмента на 7 страницах:
русские заголовки/наименования, номера, ИНН, дату, массы, десятичную цену и суммы.
Проверяется наличие текста в указанной области страницы; корректность роли
реквизита, связи строк таблицы и полнота документа не оцениваются этим числом.

Сопоставление игнорирует регистр и пробелы, но сохраняет пунктуацию числа и ведущие
нули. Числа из разных OCR-строк не склеиваются. Исходный черновик областей сохранён
локально: две денежные области FORMZ уточнены по исходнику, область ИНН ТОРГ-12
расширена до строки (движок возвращает координаты строк), разделители тысяч
приведены к тому, что напечатано в форме, исправлены позиции двух областей
паспорта щебня и области суммы встроенного УПД ВШЭ. Поэтому это демонстрационная проверка,
не слепое измерение точности с заранее независимо утверждённой разметкой.

Даже 22 совпадения не означали бы точность 100% на накладных. Для допуска к
автоматической записи заказа нужны полная разметка, новые реальные документы,
отрицательные проверки и проверка tenant/RBAC в сервисах Flowgic.

Конкретная ошибка вне выбранных контрольных фрагментов: в шапке паспорта щебня
буквы `ООО` прочитаны как цифры `000`, при этом confidence строки — около 0.981.
Высокая внутренняя оценка OCR не заменяет проверку правильности реквизита.

## Воспроизводимые команды

```powershell
C:/Python311/python.exe -m venv .local/paddle-eval/venv
.local/paddle-eval/venv/Scripts/python.exe -m pip install -r tools/document_eval/paddle_requirements.txt
venv/Scripts/python.exe tools/document_eval/download_paddle_models.py --output .local/paddle-eval/models
.local/paddle-eval/venv/Scripts/python.exe tools/document_eval/run_paddle.py --dataset .local/document-eval-ru/public-cases-v1 --models .local/paddle-eval/models --output .local/paddle-eval/run-v2 --mkldnn
venv/Scripts/python.exe tools/document_eval/check_paddle.py --results .local/paddle-eval/run-v2/results.jsonl --output .local/paddle-eval/run-v2/checks.json
venv/Scripts/python.exe tools/document_eval/render_paddle_report.py --run .local/paddle-eval/run-v2 --dataset .local/document-eval-ru/public-cases-v1
```

Существующие каталоги запусков не перезаписываются: для повторения выбрать новые имена.
Для компактного варианта скачать модели с `--detector PP-OCRv5_mobile_det` в отдельный
каталог и передать тот же флаг в `run_paddle.py` вместе с `--checks-only --mkldnn`.
Замеры двух детекторов сравнивать только по одинаковым 7 контрольным страницам.
