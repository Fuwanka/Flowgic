# Монетизация и демонстрационный контур

## Тарифы и лимиты

`billing` хранит `SubscriptionPlan` и `CompanySubscription`. Новая компания
получает FREE; существующая подключается к FREE при первом обращении к биллингу.
Миграция добавляет исходный каталог, не перезаписывая настроенные тарифы:

| Тариф | Активных ТС | Заказов в месяц | IoT |
| --- | ---: | ---: | --- |
| FREE | 3 | 30 | нет |
| PRO | 100 | 3000 | да |
| ENTERPRISE | без ограничения | без ограничения | да |

Считаются все ТС кроме `blocked` и все созданные за календарный месяц UTC заказы,
включая отменённые. При создании ТС/заказа и активации заблокированного ТС сервис
блокирует строку подписки компании в транзакции и проверяет фактические строки БД.
Так параллельные запросы не расходуют последний слот дважды. Redis хранит
показания использования на 60 секунд; кеш сбрасывается после успешного коммита.
Потеря или устаревание кеша не разрешает превышать лимит. Доступность Redis
по-прежнему необходима для авторизации и работы приложения.

JWT API для менеджера и диспетчера:

- `GET /api/billing/subscription` — план и использование своей компании;
- `GET /api/billing/plans` — каталог тарифов;
- `POST /api/logistics/orders` — создание заказа, финансовой записи и события;
- `POST /api/logistics/vehicles` — создание транспорта;
- `PATCH /api/logistics/vehicles/{id}/status` — изменение статуса транспорта.

Лимит возвращает HTTP 402 с `code=quota_exceeded`, `resource`, `limit`, `current`,
`plan_type` и понятным `detail`. Старые HTML-формы создания заказа/ТС и смены
статуса используют эти же сервисы. Данные других компаний возвращают 404;
водитель не может создавать заказы или ТС. Финансовая формула модели сохранена.
IoT пока является параметром тарифа: приём телеметрии относится к этапу 5.
Оплата и смена тарифа через публичный API не реализованы; тариф назначает
администратор или доверенный `billing.services.set_company_plan`.

## Партнёрские предложения

`marketplace` содержит `PartnerOffer` и `OfferClickLog`. Общий каталог доступен
всем компаниям, предложения с указанной компанией — только ей. Демо-офферы
всегда привязаны к демо-компании и явно помечены.

- `GET /api/marketplace/offers?context_type=dashboard|order_detail|fleet|finance&order_id=...`;
- `POST /api/marketplace/offers/{id}/click` с JSON `{ "order_id": "..." }`
  либо `{}` — сохраняет клик своей компании и возвращает целевой URL.

В карточке заказа страховой оффер появляется при превышении порога стоимости
перевозки (`agreed_price`, не объявленная стоимость груза). Факторинг связан с
неоплаченными/частично оплаченными положительными финансовыми записями компании;
топливные карты и телематика — с наличием активного транспорта. Контекст и
принадлежность заказа проверяются повторно при клике. Неактивные предложения и
опасные URL исключаются; сервер не открывает внешние ссылки и не отправляет лиды.
Наполнение реального каталога выполняется через Django Admin. Демо-ссылки ведут
на `example.com` и не представляют действующих партнёров.

## Документы

`GET /api/logistics/orders/{id}/document/docx` возвращает редактируемую
Договор-заявку; `?document_type=ttn` — ТТН. Требуется JWT менеджера/диспетчера
своей компании либо назначенного водителя. В карточке заказа также есть кнопки
скачивания через текущую сессионную авторизацию.

`docxtpl` заполняет доверенные шаблоны данными заказа, клиента, перевозчика,
водителя и ТС. XML экранируется; генерация не создаёт записей в БД и общих файлов.
OpenAPI описывает ответ как бинарный DOCX, TypeScript-клиент получает `Blob`.
Оба документа — явно обозначенные черновики: недостающие реквизиты и подписи
дополняются сторонами. Текущая модель не содержит всех полей нормативной 1-Т.
Шаблоны и инструкция их проверки: `backend/logistics/document_templates/README.md`.

## Демо-компания

После сборки и применения миграций:

```powershell
docker compose run --rm backend python manage.py seed_demo_company
```

Команда создаёт 4 клиента, 3 ТС, руководителя, диспетчера и 3 водителей,
12 перевозок с разными статусами, финансовые записи, историю и 4 демо-оффера.
Используются `logistics.factories`, маршруты Сибири и синтетические контакты.
Компания получает устойчивый UUID и явные `is_demo`, `demo_slug`, `demo_seeded_at`.
Повторный запуск не пересоздаёт записи, не меняет пароли и не отменяет ручные
изменения. Реальная компания или занятый email не могут быть присвоены командой.
Ошибка на любом шаге откатывает весь набор.

Можно указать `--slug showroom --name "Демо для презентации" --orders 20 --plan PRO`.
Для нового набора по умолчанию FREE, допустимо от 1 до 100 заказов в пределах
тарифа; в FREE — до 30. На повторном запуске только явно переданный `--plan`
меняет тариф. Параметры `--orders` и `--name` существующий набор не обновляют.

Без `--password-env` новый стойкий общий пароль демо-пользователей показывается
один раз в терминале. Для автоматизации задайте секрет в окружении и передайте
его имя, а не значение:

```powershell
docker compose run --rm -e FLOWGIC_DEMO_PASSWORD backend python manage.py seed_demo_company --password-env FLOWGIC_DEMO_PASSWORD
```

В этом режиме пароль не выводится. Адрес руководителя для стандартного slug:
`manager+flowgic-demo@demo.example.test`, диспетчера —
`dispatcher+flowgic-demo@demo.example.test`; все адреса печатаются командой.

## Проверки

```powershell
docker compose build backend test
docker compose run --rm backend python manage.py check
docker compose run --rm backend python manage.py makemigrations --check --dry-run
docker compose run --rm test python -m pytest --migrations --create-db --browser chromium --tb=short
docker compose run --rm --no-deps --volume "${PWD}/backend:/app" backend python manage.py export_openapi --output /app/openapi.json
npm run generate-api --prefix frontend-web
npm run typecheck --prefix frontend-web
```

Проверяются реальные PostgreSQL/PostGIS и Redis, миграции, конкурентная квота,
изоляция компаний, роли, атомарность, контексты офферов, клики, оба DOCX и
повторяемость демо-команды. После изменения шаблонов также требуется рендер и
визуальная проверка всех страниц.

Фактические результаты: [stage-3-verification.md](stage-3-verification.md).
