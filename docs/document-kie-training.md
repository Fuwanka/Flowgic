# Итоги неудачного эксперимента KIE и дальнейшая работа

Эксперимент 30.10.2026: RuBERT-tiny2 с координатным адаптером, 37 полей,
три стадии, 2124 шага обучения. На девяти заранее сверенных реквизитах двух
открытых документов — 0 совпадений. Эти частичные контроли не являются полной
оценкой точности. Кандидат не подключался к Flowgic.

При очистке удалены экспериментальный trainer, ML-зависимости, отдельный CI job,
локальные веса, окружение и снимки кода. Небольшие отчёты и подготовленные данные
остались в игнорируемой `.local/kie-training/` для диагностики. Они не входят в Git.

Сохранена рабочая основа: локальный PaddleOCR, приватные оригиналы, очередь Celery,
извлечение по правилам, evidence и ручная проверка диспетчером. Подробнее:
[модуль документов](ai-documents.md), [протокол набора](document-eval-ru.md).

Причины отклонения: преимущественно искусственные OCR-подобные строки вместо
разнообразных реальных страниц; только 16 частично размеченных исходников;
отсутствие визуального понимания таблиц; ограничения сборки многострочных полей.
Текущий нейросетевой декодер удалён вместе с экспериментом. Сборка многострочных
значений в рабочем извлечении также требует отдельного развития.

Следующая работа:

1. Полностью разметить реальные российские формы, сохранив отдельный test по
   источникам/макетам. Приоритет — стройматериалы, ТН/ТТН, заявки и весовые талоны.
2. Проверить объединение многострочных полей, структуру таблиц и отказ на
   отрицательных документах; сохранить различие стоимости товара и перевозки.
3. Сравнить готовые специализированные модели с действующими правилами до нового
   дообучения. Выбирать по реальным метрикам каждого поля и ручным исправлениям.
4. Обучать выбранный вариант после подтверждения разметки; неизвестные значения
   не считать отсутствующими. Не переносить результаты автоматически в заказ.

Технические тесты приложения проверяют работоспособность и изоляцию данных,
но не заменяют независимую оценку точности извлечения.
