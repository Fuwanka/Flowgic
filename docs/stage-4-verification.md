## Проверенные пользовательские цепочки

- Вход → список → фильтр завершённых заказов → календарь → карточка.
- Финансовый предпросмотр без записи → сохранение → финансовая строка и событие.
- Смена статуса → история; скачивание Договор-заявки и ТТН.
- Клик на контекстный оффер → сохранение лога → новая вкладка партнёра.
  Подменялся только внешний `example.com`; собственный API и БД оставались реальными.
- Создание клиента → новый заказ с этим клиентом → создание аккаунта водителя.
- Попытка добавить четвёртое активное ТС → HTTP 402 → окно тарифа → каталог.
- Выход → регистрация другой компании → отсутствие заказов и клиентов первой.
- Reload глубокой ссылки с восстановлением сессии вкладки → выход с очисткой.
- Экран 390 px → отсутствие горизонтального overflow страницы → drawer-навигация.
- Вход водителем → отказ в доступе к панели диспетчера.

Проверены скриншоты входа, списка, карточки, календаря, справочника, квоты и
мобильного экрана. Ожидание загрузки и отключение переходных анимаций исключают
снимки незавершённых состояний. Локальные файлы `.local/spa-qa/` не входят в Git.

## Инфраструктура и воспроизводимость

Production-бандл включён и в Nginx image, и в Docker test. Браузерные тесты
раздают этот бандл и проксируют запросы в живой Django live_server. При запуске
pytest на хосте путь к сборке определяется как `frontend-web/dist` либо `SPA_DIST`.

CI проверяет соответствие OpenAPI и SDK, TypeScript, Vitest и Vite build перед
полным pytest. Результат удалённого запуска относится к конкретному SHA в PR;
он проверяется отдельно от локальных результатов выше.

Инструкция запуска и подробная история четырёх этапов: [TRANSFORMATION.md](../TRANSFORMATION.md).
